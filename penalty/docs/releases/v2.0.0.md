# Penalty v2.0.0 — Multiplayer Public Beta

Release date: 2026-10-06. Open-source distribution target: [GitHub v2.0.0 Pre-release](https://github.com/yishan/penalty/releases/tag/v2.0.0). This version is a multiplayer public beta, not a fully endurance-tested stable release. It has not been submitted to the official FoloToy community; historical community receipts remain unchanged.

## What is new

- Nearby two-device Shootout: choose Create Lobby or Join Lobby. Match the four-digit lobby code, compare the six-digit security values, confirm the shared difficulty, then let the creator toss the coin. Creating a lobby does not guarantee the first kick.
- Both people choose their targets and timing independently, without seeing an opponent's direction cue. Alternate shooting and keeping through five regular rounds, early finish when appropriate, and paired sudden death on a tie.
- The creator shoots in red, the joiner in blue, and the keeper wears black on both screens. Each round contains one kick per player, in both AI and multiplayer matches.
- Reconnect within the 30-second window without a new coin toss, changed locked choices, or duplicate scoring. A timeout ends the match without a winner. Restarting a device does not restore its match.
- Clearer menu spacing, wraparound navigation, `>> selection <<` markers, improved cover typography and balanced character sizes. Chinese and English remain available.
- Smaller firmware through size-oriented compilation, unused-theme removal, lossless font compression and transparent-border trimming; gameplay rules and visible asset pixels are retained.

## Validation boundary

Earlier device sessions cover both create/join roles, matching results, short recovery and no-contest timeout behavior. On 2026-10-06 the user accepted the optimized development build's requested menu, animation and audio checks on the second device. These are bounded observations, not acceptance of the newly versioned normal release binary.

The exact normal v2.0.0 app was subsequently installed on one device. Its write verification, independent Flash verification, unchanged partition table and over-25-second startup observation passed; the startup reports version `2.0.0`. Physical gameplay on this exact normal binary remains pending. The complete M6 matrix is not finished: sustained play, repeated reconnect/entry-exit cycles, all disconnect phases, multiple nearby lobbies, security/compatibility exceptions, runtime resource peaks and instrumented timing/power remain unverified where no explicit device evidence exists. See the [validation record](../validation.md) and [M6 checklist](../plans/2026-09-24-ble-duel-v2-design.md).

## Deliverables and installation boundary

The local package is `build/community/penalty-v2.0.0/`. It contains the normal merged firmware, SHA-256 checksums, this bilingual release note, bilingual listing metadata, a local publisher preview, a cover capture, and two Chinese Shootout submenu captures. All three PNGs are native 240 × 320 desktop captures of the actual LVGL UI; they are not physical-device photographs or serial screenshots.

`FoloToy-AI-Passport-Penalty-v2.0.0-full.bin` is a merged factory-layout image for offset `0x0`. It includes bootloader, partition table and application. It is **not** an app-only OTA/Launcher image. Installing it replaces the existing boot/partition layout and can make prior apps/resources inaccessible; back up any user data that must be retained. Do not use it for an in-place resource-preserving app update. Such an update needs a separately verified app-only image and the live device's compatible partition layout.

GitHub release assets additionally provide `FoloToy-AI-Passport-Penalty-v2.0.0-app.bin`, the exact normal app verified on the device (1,572,864 bytes). Its SHA-256 is `dee3cf9697658ca37224a81b6d7cd51700b634906a5486b1c49dce9c69cf7bb4`; the full image is 1,638,400 bytes, SHA-256 `6dd9489d301cb73e61e65f76e78f5deb680e23315c17732246b7d69b5b2a42ee`. The app-only file must never be written at `0x0`; determine the actual compatible app partition before installation. Launcher lifecycle code is included, but this release's Launcher slot/rollback/return path has not been device-tested.

GitHub's source archives contain the application-layer export, not a standalone firmware project. Follow the public repository's pinned-baseline `apply.sh --dry-run` workflow. Code is MIT with existing notices retained; bundled font and audio licenses remain separate. GitHub publication does not submit or update the official community listing.
