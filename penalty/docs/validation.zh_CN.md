`<port>` 是占位符，不能原样输入（macOS 端口通常以 `/dev/cu.usbmodem` 开头，Windows 使用 `COM` 端口）。使用图形化 ESP32 刷写工具时，选择相同芯片、文件和地址。不要把 app-only 镜像写到 `0x0`。这是本文档记录的真机验证所使用的命令。

第一轮先快速检查：方向正确、左右映射、一局五球、声音／静音、长按 OK 退出恢复竖屏。如有问题，请提供出错步骤、实际与预期的差异，以及短视频或脱敏串口日志，并说明能否稳定复现。

## 真机验收清单

空白设备使用经验证的合并镜像；需要保留现有 NVS 时，依照仓库[构建说明](../../docs/development/engineering/build-and-test.zh_CN.md)选择分段烧录。v1.1 镜像已通过这份清单的真机验证。

1. 刷入合并镜像后开机，首个应用画面应为已确认的竖屏像素封面并显示英文横转提示，不再显示 FoloToy 或 Display／Button 菜单，也不显示任何电量文字。设备顺时针横握（原顶部向右）后按一次 OK，标题应正向显示、铺满 320 × 240 逻辑画面、四角黑色圆角正确，并在顶栏显示实时电量。
2. 打开“设置”，循环简单／普通／困难，切换音效，再将语言改为简体中文。确认当前页面立即切换，四行均完整显示；返回标题后打开“说明”，检查中文无缺字、清晰且不裁切。回到设置选定难度，再开始游戏。确认绿区宽度为 20／11／6 格，内部深绿线为两格。从初始中上格开始，连续按物理 UP，确认中上→右上→左下→中下→右下→左上→中上；物理 DOWN 按完全相反的顺序循环。两排内部必须始终保持 UP 向右、DOWN 向左。OK 开始蓄力，另一次 OK 锁定。进入游戏的动作不得同时启动射门。
3. 确认六格边框和亮色选中框均清晰可读；蓄力前可见区域，蓄力中固定，下一球换位置。双向经过绿区都减速，检查深绿线的实际可读性与按键时机。体验弱射、深绿线进球／扑出、普通绿区进球／扑出、绿区外进球／扑出、过高和超时；球落点、门将格、结果文案、音效类别须一致，每球恰好记录一次。90%／65%／25% 的精确平均值已有自动模型证据，少量真机随机结果不能重新统计验证。
   简单模式每球保留本地化后的深绿线教学；普通／困难仅第一球显示，之后的本地化鼓励文案在瞄准／蓄力期间保持不变，相邻球不重复，第五球使用专属收官文案。中英文结果解说均须与实际判定一致且不得裁切。
4. 完成五球、重玩、返回标题、切换音效、静音重玩；重玩／标题保留难度和静音，返回封面重置两者。语言应在封面、再次进入游戏及正常断电重启后保持中文；切回英文后重复一次重启检查。不得出现虚构的对手比分或加罚。
5. 从横屏菜单打开“说明”，按 OK 返回菜单。在封面、标题、设置、说明、瞄准、蓄力、飞行、结果、总结分别长按 OK，声音应停止并恢复竖屏封面。松开 OK 不得自动重进横屏菜单。立即重进，确认旧按键／旧音效不会进入新一局。
6. 在封面／标题／玩法／瞄准／总结等待 60 秒，检查变暗和仅唤醒一次按键、不误射门；确认封面始终无电量文字，横屏页面的电量／未知电量文字完整且更新不影响游玩。
7. 连续游玩 20 局并执行 50 次进入／退出，查看 `penalty` 日志中的进入／退出堆、最大连续块、最小堆、worker 栈余量、`max_update_us`、`max_input_age_ms`。比较预热后的数据，不应持续丢失堆、泄漏任务、触发看门狗或重启。
8. 测量输入到可见反馈是否达到 100 ms 目标，动画是否达到暂定 20 FPS。`max_update_us` 仅是模型／UI 更新耗时，不包含最终绘制／SPI 传输；它和宿主截图均不能证明实物帧率。检查实物尺寸下的按键触达、反光、文字可读性和圆角裁剪。
9. 先按固件内置的 60% 音量试听。确认蓄力、踢球、普通进球、精准进球、普通／绿区／深绿线扑救、弱射、过高／超时、难度、静音和五球结束提示可区分；超时不得出现踢球声。用慢动作视频检查踢球声开始与画面 100 ms 触球点相差约 50 ms 以内。检查削波／杂音、SOUND 关闭前最后提示、重新开启提示、快速退出重进取消及连续 20 局。只有确有需要再索取 40%／80% 校准固件。在受控开发环境中测试音频／电量不可用，以及 worker／旋转失败，确认可安全恢复且长按 OK 有效。

待验证：实际旋转方向、中文实物可读性与语言持久保存、输入延迟、显示帧率、音频质量、电量读数、系统堆／任务栈、故障注入和真机耐久循环。
