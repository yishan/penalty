# Penalty — 游戏策划大纲

版本：1.0 · 日期：2026-09-16 · 阶段：六格射门与标定概率已接入。[验证状态](validation.zh_CN.md)区分宿主、固件与真机证据；[多语言设计](localization.zh_CN.md)记录语言菜单、持久保存、字库子集和溢出策略。

## 1. 游戏概念与玩家目标

一款适合碎片时间、运行于 AI Passport 的离线像素点球游戏。玩家用三键选择目标、把握射门时机，随后得到清晰的进球、扑出或偏出反馈。目标单局时长约 30–90 秒；这是试玩目标，不是强制倒计时。

核心乐趣是选方向与把蓄力游标停在最佳区间。完美射门应明确奖励操作时机，让玩家感到成绩能够通过练习提升。

本大纲承接 Codex 任务 `01a0a2a6-7e5c-7dd2-af45-4c5d90ef5403` 中的点球／Pong 可行性讨论。v0.2 采纳用户提出的横屏方案：进入提示、画面向左旋转 90°、UP 对应右、DOWN 对应左、OK 确认。v0.3 采纳已确认的竖屏像素开机封面与独立游戏入口；v0.9 将难度、音效和语言集中到“设置”，并加入可持久保存的英文／简体中文选择。开发无需先做 Pong。

## 2. 范围与版本规划

| 阶段 | 包含内容 | 完成条件 |
| --- | --- | --- |
| MVP：射门挑战 | 离线单人；上下六格；两次按键控制蓄力；六格 AI 守门；五球；结算；重玩；静音；短音效 | 真机可完整进行五球挑战，操作和结果清晰 |
| 下一阶段：守门挑战 | AI 射门五次；玩家选择方向，在可见时机窗口内确认扑救 | 方向与时机均影响结果，过早／过晚有明确说明 |
| 后续：交替攻守点球大战 | 玩家与 AI 交替射门、守门；五轮；提前胜出与突然死亡加罚 | 攻守顺序、胜负规则通过宿主测试 |
| v0.4：难度 | 简单／普通／困难；随机绿区；两格必进线；绿区减速 | 规则／渲染自动检查，真机时机验收待完成 |
| v1.0：六格规则 | 两行三列目标；环形切换；六格门将；90%／65%／25% 平均进球率 | 穷举模型概率及实际 LVGL 目标／轨迹检查通过 |
| 可选扩展 | 本地最佳成绩、更多美术 | 实测输入、内存和帧耗时后再加入 |

MVP 没有对手比分、胜负或加罚：它是计分为 0–5 的五球挑战。3/5 即结束，不构成平局。交替攻守模式中，双方各最多罚五球；落后方已不可能追平时提前结束。各罚五球后平分，则每方各罚一球，完整一对结束后比分不同才分胜负，不能在加罚的第一方射门后直接结束。

不包含：自由跑动足球、3D 物理、联网、排行榜、多人对战、语音控制、背景音乐、硬件改造。

## 3. 硬件与设计边界

| 当前基线 | 设计约束 |
| --- | --- |
| ESP32-C3、8 MB Flash、无 PSRAM | 小对象、紧凑素材，游戏不分配全屏帧缓冲 |
| 物理屏幕 240 × 320 RGB565；40 MHz SPI | 游戏逻辑坐标为 320 × 240 横屏，画面向左旋转 90°；局部刷新，暂定 20 FPS 动画目标 |
| 当前 LVGL 单缓冲为 20 行 | 首先沿用，测量刷新开销后再考虑扩大 |
| UP／DOWN／OK 共用 ADC 电阻梯 | 单键顺序操作，不依赖组合键或按住方向键 |
| BSP 已暴露 PRESS、CLICK、DOUBLE、LONG | 关键时机使用 PRESS，不再重复处理后续 CLICK／DOUBLE |
| ES8311 音频支持 | 短音效入队播放；音频故障不得阻止射门 |

硬件／接口依据：[引脚定义](../../components/bsp/include/bsp_pins.h)、[显示实现](../../components/bsp/src/bsp_display_lvgl.c)、[按键接口](../../components/bsp/include/bsp_button.h)、[产品规格](../../docs/hardware-design/specifications.zh_CN.md)。原讨论低估了现有 PRESS 支持，当前头文件和实现已提供按下事件。帧率、延迟、空闲堆与续航均尚未实测。

## 4. 操作设计

### 横屏引导与进入

开机直接显示已确认的 240 x 320 竖屏像素封面：PENALTY 标题、底部操作区顶部同为米白粗字／深色阴影风格的“点球决胜”、面对球门的球员、横向草坪明暗带、黑色球衣门将及顺时针横握图示；封面刻意不叠加电量。内嵌文案：`TURN RIGHT 90° / THEN PRESS OK`。设备原顶部朝右，按 OK 继续。确认后进入 320 × 240 游戏标题页，其画面相对原竖屏方向向左旋转 90°，实时电量在横屏顶栏显示；标题页只展示球场和菜单，不再显示原 `MAKE IT COUNT.`／“一球定胜负”副文案。这是固定的直角旋转，不是透视倾斜效果。

由用户按键确认，不依赖自动方向检测。消费本次 OK 事件，避免同时触发开始游戏。标题、设置、游玩、结果与重玩流程均保持横屏，重玩不重复引导。退出时先停止游戏，恢复竖屏并重置输入代次，直接返回竖屏封面。正常流程不再显示硬件演示菜单。

### 按键映射

UP 沿目标环顺时针前进，DOWN 逆时针返回，OK 确认。顺序为左上→中上→右上→右下→中下→左下→左上。设备顺时针横握后，UP／DOWN 对应界面上的右／左选择键。标题菜单包含“开始、设置、说明”；设置页包含“难度、音效、语言、返回”。DOWN 选择前一项，UP 选择后一项。每球默认从中下格开始，六格首尾循环。

| 页面／状态 | UP／DOWN | 短按 OK | 长按 OK |
| --- | --- | --- | --- |
| 竖屏封面 | 无操作 | 切换到横屏菜单 | 重置为竖屏封面 |
| 标题页 | 选择开始、设置或说明 | 执行所选项目 | 返回竖屏封面 |
| 设置 | 选择难度、音效、语言或返回 | 循环／切换设置，或返回标题 | 返回竖屏封面 |
| 玩法 | 无操作 | 返回横屏菜单 | 返回竖屏封面 |
| 瞄准 | 正反向循环选择六格 | 锁定目标，开始蓄力 | 退出本局 |
| 蓄力 | 无操作 | 锁定力度并射门 | 退出本局 |
| 飞行／单球结果 | 无操作 | 无操作，自动转场 | 退出本局 |
| 总结 | 选择再来一局或标题页 | 执行选项 | 返回竖屏封面 |

蓄力是两次独立按键，不是按住再松开。一次物理按键只产生一次游戏动作。进入游戏的按键不能同时启动射门，队列中的旧输入不能推进新页面。菜单可使用有延迟的 CLICK；瞄准／蓄力使用带事件时间戳的 PRESS，忽略其后续 CLICK／DOUBLE，LONG 负责退出。一次 OK 按下可能先触发短暂动作，再被识别为长按；退出时取消本局并丢弃结果。MVP 不设暂停。

沿用长按 OK 退出的现有约定。后续输入集成需明确把 PRESS 路由到游戏，并测试导航处理权，不能仅因头文件存在事件就假定页面分发正确。

## 5. 射门规则——v1.0 标定概率

1. 每局从 0 个进球、5 个空结果位开始。
2. 每个新球进入瞄准时，生成绿区、内部深绿线、在同样六格中等概率选定的门将目标，以及一个 0–99 结果随机值。蓄力前即显示区域与六格，门将目标和随机值不揭示。瞄准、蓄力、迟到输入恢复时均不重抽；开始蓄力时锁定射门目标。
3. 游标从 0 升到 100 再返回；普通力度每格 8 ms，绿区每格 40 ms（原速的五分之一），升降双向一致。力度由单调时钟的经过时间计算，不依赖帧数。4,000 ms 内未锁定则判超时偏出，消耗一球。瞄准阶段不设超时。
4. 第二次 OK 锁定力度，按下表一次性确定结果；所有端点均包含在对应区间。

| 力度 | 结果 |
| --- | --- |
| 0–29 | 扑出：力度太弱，无论门将原选方向如何均可收球 |
| 深绿线（绿区内 2 格） | 精准射门；六格门将等概率预判后平均 90% 进球 |
| 其余绿区 | 六格门将等概率预判后平均 65% 进球 |
| 30–90 的绿区外 | 六格门将等概率预判后平均 25% 进球 |
| 91–100 | 偏出：力度过大，球越过球门 |

| 难度 | 绿区宽度（含端点的力度格） | 完整往返周期 | 每次经过深绿线的窗口 |
| --- | --- | --- | --- |
| EASY 简单（默认） | 20，来自原提议 61–80 | 2,880 ms | 80 ms |
| NORMAL 普通 | 11，来自原提议 70–80 | 2,304 ms | 80 ms |
| HARD 困难 | 6，来自原提议 75–80 | 1,984 ms | 80 ms |

原提议区间仍定义宽度，不固定位置。每球绿区完全位于 30–90 内，相邻同宽绿区的起点不同。2 格深绿线在绿区内随机摆放，可以贴任一边缘。命中深绿线就计入完美／精准次数，无论最终进球或被精彩扑出。下表保证门将等概率选六格时，每个玩家目标都得到指定平均值；它们是长期概率，不是每局配额。

| 力度区域 | 门将完全同格 | 同列但上下错层 | 其他列 | 六格平均 |
| --- | ---: | ---: | ---: | ---: |
| 深绿线 | 75% 进球 | 85% 进球 | 95% 进球 | 90% 进球 |
| 其余绿区 | 30% 进球 | 40% 进球 | 80% 进球 | 65% 进球 |
| 绿区外、30–90 | 0% 进球 | 10% 进球 | 35% 进球 | 25% 进球 |

难度只改变可见绿区宽度。力度时序保持普通每格 8 ms、绿区每格 40 ms；更高难度不暗加速度或改变概率。

这是街机规则，不模拟真实足球物理。明确显示六格球门、亮色选中框、绿区、带浅色边线的深绿线及 91–100 红色危险区；游标在蓄力条上下标记，不遮住深绿线。进球时足球飞向已选上／下格，门将按隐藏预判移动；扑救时球停在实际球路的手套接触点。深绿线被扑使用扑救音效和独立结果。动画解释已算出的结果，不通过视觉碰撞反推判定。

难度在 PLAY 前选择，一局内固定。重玩和返回标题保留难度；返回竖屏封面或重启恢复 EASY，静音设置保留范围相同。必须在真机检查细线可读性，以及 80 ms 窗口配合现有 50 ms 界面更新周期的手感；宿主时间计算不代表响应实测。

5. 球和门将动画约 600 ms，随后展示结果与原因 900 ms；超时直接展示结果。每球只记一次。第 1–4 球后回到瞄准，第 5 球后进入总结。
6. 总结显示进球数／5、五次结果、深绿线命中次数，以及再来一局／标题页，不自动重开。

进球、完美、普通绿区进球、绿区扑出、弱射扑出、普通扑出、踢高和超时反馈均已本地化。中英文都采用经过实际 LVGL 布局宽度检查的短文案；简体中文使用仅包含游戏所需字符的思源黑体子集渲染。

底部文案仅在 EASY 或第一球承担教学；NORMAL／HARD 后续每球固定显示一句相邻不重复的鼓励，结果区按判定显示轻松解说。蓄力过程中不换句，也不消耗玩法随机数。完整文案和边界见[动态文案设计](plans/2026-09-16-dynamic-copy-design.zh_CN.md)。

门将六格目标由纯逻辑中的可设种子生成器产生，并在玩家提交目标和力度前锁定。测试注入固定种子／决策，设备集成提供每局种子。未来更高难度不得偷看已提交的玩家选择后暗中修改决定。

## 6. 页面与状态流程

```text
开机 → 竖屏封面 → 横屏菜单（开始／设置／说明）
设置（难度／音效／语言／返回）→ 标题
玩法 → 标题（OK）
标题 → 瞄准 → 蓄力 → 飞行 → 单球结果 → 瞄准（第 1–4 球）
               └─ 超时 ──→ 单球结果 → 总结（第 5 球）
总结 → 瞄准（再来一局，重置）／标题
任意活动状态 → 退出中 → 恢复竖屏 → 封面
```

飞行与超时共用同一套“下一球／总结”分支。重复接收结果不能重复记分。退出时先停止事件生产，再销毁画面。

320 × 240 逻辑横屏布局建议，文字与操作提示随整个画面统一旋转。坐标为设计目标：

| 区域 | 纵向范围 | 内容 |
| --- | --- | --- |
| 顶栏 | y=0–17 | 难度、第 1/5 球、进球数、电量 |
| 球场 | y=18–182 | 素材球场、目标提示、射手、门将、独立足球与阴影 |
| 蓄力／结果 | y=182–203 | 水平蓄力条、最佳区、游标或结果文案 |
| 底栏 | y=204–239 | LEFT／RIGHT 箭头、OK 提示、小号退出提示 |

关键文字和控件避开圆角，初始放在 x=32–287 范围内。利用增加的宽度拉开三个射门区域。这里是逻辑横屏坐标，不通过交换硬件引脚表中的宽高常量实现布局。

风格：深绿球场、白色门线、明亮足球、原创中性球员像素形象、清晰轮廓。用文字／形状辅助区分区域和结果，不只依赖颜色。蓄力中保留选中目标。用缩放和位移表现纵深，不引入 3D 渲染；避免镜头移动、全屏特效、真实俱乐部品牌和球员肖像。

音频：射门、进球、扑出、偏出短提示，初始每段不超过 300 ms。一个 worker 搭配有界队列，快速转场时丢弃过时音效。声音默认开启，静音只在本次运行中保留；不使用麦克风。

## 7. 开发结构

按用户要求，以 `penalty/` 作为项目策划／设计入口；固件继续沿用当前 ESP-IDF 应用及仓库职责边界：

| 计划模块 | 职责 |
| --- | --- |
| `main/penalty_model.{c,h}` | 纯 C 规则、可复现随机决策、时钟输入、状态转换、每球记录 |
| `main/penalty_ui.{c,h}` | LVGL 对象、布局、反映模型结果的动画 |
| `main/penalty_app.{c,h}` | 输入路由、生命周期、时钟／随机种子适配、音频队列 |
| `tests/test_penalty_model.c` | 规则、时机、状态转换、重复输入及重置的宿主测试 |
| `penalty/assets/`（需要时创建） | 可编辑的美术／音效源素材及授权说明 |

模型不引用 ESP-IDF 或 LVGL 头文件。每局数据包含状态、球次、进球数、完美次数、玩家／门将方向、力度、时间戳、种子和五条射门记录。每球记录包含方向、力度、门将决策和结果／原因，不含玩家身份或联网数据。

模型由单一执行者修改。按键回调只投递有界事件并返回。LVGL 任务外访问 UI 时持有 `bsp_lvgl_lock()`；音频与语言偏好的 NVS 写入在锁外 worker 中执行。销毁顺序：停止定时器、拒绝旧会话事件、刷新待写入语言、停止并等待 worker 退出，再删除 UI 对象。若 worker 未能停止，保留画面，直到可以安全清理。

`main/main.c` 现为独立游戏入口，开机直达 Penalty。基线演示源文件保留作参考，但不再链接进本游戏。返回封面时停止定时器和服务 worker，恢复竖屏，重建画面，推进输入代次，再启动服务。已确认封面以 153,600 字节的 const RGB565 数组存于 Flash，不在 RAM 解码整图。源图与转换步骤见[资源说明](../../assets/README.zh_CN.md)。没有增加分区、改引脚或复制 BSP。

旋转通过 `bsp_lvgl_set_landscape()` 使用已锁定 esp_lvgl_port 2.9.0 的硬件旋转路径，`rounded_flush_event()` 已改为读取当前逻辑尺寸。局部缓冲容量保持不变，没有分配全屏旋转缓冲。方向在 LVGL 锁内切换／恢复，设置失败时尝试回滚并允许重试。旋转、圆角遮罩、返回封面后的方向恢复仍需真机验证。

## 8. 存储、异常与性能

- MVP 在 RAM 保存进度、难度和静音设置。退出或断电即丢弃本局，不宣称续玩或成绩已保存。语言是唯一持久保存的游戏设置，从现有 NVS 分区恢复。
- 可选的最佳成绩用带版本号的小型 NVS 记录，在结算时写入。NVS 失败则退化为本次运行成绩，并明确提示未保存。本设计不要求改动分区。
- 飞行／结果阶段忽略无效操作，丢弃旧会话输入。队列溢出不得重复射门或产生任意延后的射门；提交前恢复到瞄准，已提交则完成既定结果。
- 音频初始化失败仍可静音游玩。UI 分配失败时停止已创建资源，显示带长按 OK 重试提示的最小错误页，不保留残缺页面。
- 局部刷新动画目标为 20 FPS，延迟一帧不应改变时间计算；游玩中输入到可见反馈目标不超过 100 ms。两项均需真机测量。
- 游玩中保持 LVGL 对象数量固定，球次之间复用对象；封面只读图片不进入运行堆。新增本地化文案必须同时通过生成字库字符契约和实际 LVGL 宽度检查。真机测试记录最小空闲堆、最大连续空闲块、任务栈余量、显示更新耗时，再据此制定资源预算。

## 10. 首个可玩版本之后再评估的决策

当前实现基线为：先射门、提示后横屏游玩、正反向六格目标环、时机蓄力、六格门将及 90%／65%／25% 标定平均进球率、五球挑战、中性像素美术、中英文 UI、语言持久保存、成绩仅保存在 RAM。试玩重点判断六格循环是否舒适、上下格与中文在实物屏幕上是否清晰、20 FPS 是否响应及时，再决定守门模式、交替攻守或成绩持久化的下一步优先级。
