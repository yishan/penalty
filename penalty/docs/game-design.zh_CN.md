# Penalty — 游戏策划大纲

版本：1.5 · 日期：2026-09-23 · 阶段：点球决胜与竖屏射门／守门练习已在本地接入。[验证状态](validation.zh_CN.md)区分宿主、固件与真机证据；[多语言设计](localization.zh_CN.md)记录语言菜单、持久保存、字库子集和溢出策略。

当前开发增量：[BLE v2 对战设计](plans/2026-09-24-ble-duel-v2-design.zh_CN.md)为“点球决胜”增加单机／创建大厅／加入大厅／返回。除明确标注 PvP 的内容外，下文规则仍描述保留的 v1.5 单机模式。PvP 使用双方同时盲选、创建方触发随机抛硬币、经认证的四位大厅码／六位安全比较流程，以及 30 秒恢复和超时无胜负中止；不提供 AI 射手动作提示。M5 覆盖双语渲染、单机／Launcher 兼容与固定资源；M6 真机／安全／耐久验收另列。未修改的 `penalty/VERSION` 用于兼容文件名，不代表 v2 已发布。

## 1. 游戏概念与玩家目标

一款适合碎片时间、运行于 AI Passport 的离线像素点球游戏。玩家可进行完整点球决胜，也可选择独立射门／守门练习，用三键在六格中选择目标、把握动作时机，随后得到清晰结果。目标单局时长约 30–90 秒；这是试玩目标，不是强制倒计时。

核心乐趣是选方向与把蓄力游标停在最佳区间。完美射门应明确奖励操作时机，让玩家感到成绩能够通过练习提升。

本大纲承接 Codex 任务 `01a0a2a6-7e5c-7dd2-af45-4c5d90ef5403` 中的点球／Pong 可行性讨论。v0.2 引入早期横屏流程；v0.3 加入已确认的竖屏像素封面与独立游戏入口；v0.9 将难度、音效和语言集中到“设置”，并加入可持久保存的英文／简体中文选择。v1.3 将全流程改为 240 × 320 竖屏并改用上下轮询目标；v1.4 新增独立守门挑战。开发无需先做 Pong。

| --- | --- | --- |
| MVP：射门挑战 | 离线单人；上下六格；两次按键控制蓄力；六格 AI 守门；五球；结算；重玩；静音；短音效 | 真机可完整进行五球挑战，操作和结果清晰 |
| v1.4：守门挑战 | AI 射门五次；蓝衣射手给出真实动作提示；玩家选择黑衣门将方向，在可见时机窗口内确认扑救 | 六种提示、时机区间、结果、动画、声音与双语界面通过宿主／渲染检查 |
| [v1.5：点球决胜](plans/2026-09-23-shootout-mode-design.zh_CN.md) | 玩家与 AI 交替射门、守门；抛硬币定先手、五轮、提前胜出与不限轮数的成对突然死亡 | 纯 C 规则、固定内存、双语 LVGL 流程及桌面渲染已本地通过；固件与真机验收待完成 |
| v0.4：难度 | 简单／普通／困难；随机绿区；两格必进线；绿区减速 | 规则／渲染自动检查，真机时机验收待完成 |
| v1.0：六格规则 | 两行三列目标；环形切换；六格门将；90%／65%／25% 平均进球率 | 穷举模型概率及实际 LVGL 目标／轨迹检查通过 |
| 可选扩展 | 本地最佳成绩、更多美术 | 实测输入、内存和帧耗时后再加入 |

MVP 没有对手比分、胜负或加罚：它是计分为 0–5 的五球挑战。3/5 即结束，不构成平局。交替攻守模式中，双方各最多罚五球；落后方已不可能追平时提前结束。各罚五球后平分，则每方各罚一球，完整一对结束后比分不同才分胜负，不能在加罚的第一方射门后直接结束。

不包含：自由跑动足球、3D 物理、互联网／云端对局、排行榜、语音控制、背景音乐、硬件改造。本地双人 BLE 仅属于上述实验性 v2 增量，不改变离线单机规则。

## 3. 硬件与设计边界

| 当前基线 | 设计约束 |
| --- | --- |
| ESP32-C3、8 MB Flash、无 PSRAM | 小对象、紧凑素材，游戏不分配全屏帧缓冲 |
| 物理屏幕 240 × 320 RGB565；40 MHz SPI | 游戏使用原生 240 × 320 逻辑坐标；局部刷新，暂定 20 FPS 动画目标 |
| 当前 LVGL 单缓冲为 20 行 | 首先沿用，测量刷新开销后再考虑扩大 |
| UP／DOWN／OK 共用 ADC 电阻梯 | 单键顺序操作，不依赖组合键或按住方向键 |
| BSP 已暴露 PRESS、CLICK、DOUBLE、LONG | 关键时机使用 PRESS，不再重复处理后续 CLICK／DOUBLE |
| ES8311 音频支持 | 短音效入队播放；音频故障不得阻止射门 |

硬件／接口依据：[引脚定义](../../components/bsp/include/bsp_pins.h)、[显示实现](../../components/bsp/src/bsp_display_lvgl.c)、[按键接口](../../components/bsp/include/bsp_button.h)、[产品规格](../../docs/hardware-design/specifications.zh_CN.md)。原讨论低估了现有 PRESS 支持，当前头文件和实现已提供按下事件。帧率、延迟、空闲堆与续航均尚未实测。

## 4. 操作设计

### 竖屏进入

开机直接显示已确认的 240 × 320 像素封面：PENALTY 标题、米白粗字／深色阴影风格的“点球决胜”、面对球门的球员、横向草坪明暗带、黑色球衣门将及无框开始提示（中文“按 确认 开始”，英文 `PRESS OK`）。现有中文像素字放大至 307/256（约 120%），向下移 6 像素以增加上方留白。使用源图片 (56,232)、128 × 19 的只读裁剪，在 (43,238) 绘制，保留原风格及 480 字节源行跨度。旧字以现有草坪各行颜色覆盖；源图不改，不新增图片缓冲或控件。提示使用与长按确认返回提示一致的灰绿色 `0xA2BC9E`。现有文本控件以 `0x093A20` 背景覆盖图片中的旧框，范围为 x=40、y=263、宽 159、高 33。旧／新像素字及提示区域以外的像素保持不变。中英文提示继续使用 14 像素中文子集字体，文字基线位置保持。封面刻意不叠加电量。设备保持竖直，按 OK 后进入 240 × 320 标题页，实时电量从标题页开始显示；标题页只展示球场和菜单，不再显示原 `MAKE IT COUNT.`／“一球定胜负”副文案。

消费本次 OK 事件，避免同时触发开始游戏。标题、设置、游玩、结果、重玩与封面全程保持竖屏，重玩不重复显示封面。退出时先停止游戏并重置输入代次，再直接返回竖屏封面。停止路径可幂等请求恢复竖屏作为安全措施，但正常游戏不再进入横屏。正常流程不显示硬件演示菜单。

封面消费实体 PRESS，等待区分短按与长按。短按 OK 使用已确认的 CLICK 时间戳进入标题，不回填最初 PRESS 的时间戳；正常单击识别等待不能触发游戏的 100 ms 过期输入保护或显示重试提示。比赛时机仍使用原始 PRESS 时间戳。封面长按 OK 仍被消费，不开始游戏，也不返回 Launcher。

### 按键映射

UP／DOWN 上下轮询目标，OK 确认。每次尝试从中上开始；DOWN 按“中上→中下→左上→左下→右上→右下→中上”循环，UP 完全反向。同一列的两格因此先按实体上下方向移动，走完后才切换到下一列。标题菜单包含“点球决胜、点球练习、守门练习、设置、说明”；设置页包含“难度、音效、语言、返回”。两个菜单中，DOWN 选择后一项并从末项回到首项，UP 选择前一项并从首项回到末项。移动选中项不修改设置，按 OK 才执行。

标题顶部球场视口高 90 像素。中英文标题菜单均隐藏装饰性页眉和选择／确认提示，保留电量与长按 OK 返回封面的提示。封面也隐藏装饰性页眉。五行菜单从 y=116 开始，每行占 32 像素。设置页四行从 y=84 开始，每行占 40 像素。决胜二级菜单（单机对战 AI／创建／加入／返回）及最多四个搜索到的大厅也从 y=84 开始，每行占 40 像素，不保留末尾空行。玩法说明保留三行操作正文，从 y=84 开始，每行占 32 像素，不显示概率百分比行；仅删除说明文案，不改变时机条或游戏概率。保留现有 14 像素字体。标题／设置／二级菜单／大厅选中项改为 `>> 菜单项目 <<`，未选中项不带标记；结果页的重试／标题选择也使用同样样式，两个选项之间保留四个空格。行间距按每种语言字体的实际行高补足。不扩大 LVGL 池或绘制缓冲。封面提示的颜色／内边距／背景及菜单行距在其他页面恢复默认，避免样式继承或裁切。设置／说明／联机的页眉与操作提示保持可见。

比赛页眉按双方配对回合计数，不按单球计数：第 1／2 球均显示第 1 回合，第 3／4 球均显示第 2 回合。两球的瞄准、蓄力、等待、动画及结果保持当前回合号。AI 常规第二球结果页不提前递增，在下一次交接时进入下一回合；AI 加赛保留现有单独标注的配对回合序列。BLE 页眉从已同步的一基逐球 ID 派生回合号，不修改协议 ID 或结算规则。比分仍以本机玩家为前。练习模式保留五次尝试计数。

| 页面／状态 | UP／DOWN | 短按 OK | 长按 OK |
| --- | --- | --- | --- |
| 竖屏封面 | 无操作 | 进入竖屏菜单 | 重置为竖屏封面 |
| 标题页 | 选择点球决胜、点球练习、守门练习、设置或说明 | 执行所选项目 | 返回竖屏封面 |
| 抛硬币／结果 | 无操作 | 抛硬币，再确认已锁定的先手角色 | 放弃比赛并返回封面 |
| 攻守交接 | 无操作 | 开始页面提示的射门或守门回合 | 放弃比赛并返回封面 |
| 设置 | 选择难度、音效、语言或返回 | 循环／切换设置，或返回标题 | 返回竖屏封面 |
| 玩法 | 无操作 | 返回竖屏菜单 | 返回竖屏封面 |
| 瞄准 | 按列正反向循环选择六个射门／扑救格 | 锁定目标，开始时机条 | 退出本局 |
| 蓄力 | 无操作 | 锁定时机并射门／扑救 | 退出本局 |
| 飞行／单球结果 | 无操作 | 无操作，自动转场 | 退出本局 |
| 总结 | 选择再来一局或标题页 | 执行选项 | 返回竖屏封面 |

蓄力是两次独立按键，不是按住再松开。一次物理按键只产生一次游戏动作。进入游戏的按键不能同时启动射门，队列中的旧输入不能推进新页面。菜单可使用有延迟的 CLICK；瞄准／蓄力使用带事件时间戳的 PRESS，忽略其后续 CLICK／DOUBLE，LONG 负责退出。一次 OK 按下可能先触发短暂动作，再被识别为长按；退出时取消本局并丢弃结果。MVP 不设暂停。

沿用长按 OK 退出的现有约定。后续输入集成需明确把 PRESS 路由到游戏，并测试导航处理权，不能仅因头文件存在事件就假定页面分发正确。

## 5. 射门规则——v1.0 标定概率

1. 每局从 0 个进球、5 个空结果位开始。
2. 每个新球进入瞄准时，生成绿区、内部深绿线、在同样六格中等概率选定的门将目标，以及一个 0–99 结果随机值。蓄力前即显示区域与六格，门将目标和随机值不揭示。瞄准、蓄力、迟到输入恢复时均不重抽；开始蓄力时锁定射门目标。
3. 游标从 0 升到 100 再返回；普通力度每格 8 ms，绿区每格 40 ms（原速的五分之一），升降双向一致。力度由单调时钟的经过时间计算，不依赖帧数。4,000 ms 内未锁定则判超时偏出，消耗一球。瞄准阶段不设超时。
4. 第二次 OK 锁定力度，按下表一次性确定结果；所有端点均包含在对应区间。

| 力度 | 结果 |
| --- | --- |
| 0–29 | 扑出：力度太弱，无论门将原选方向如何均可收球 |
| 深绿线（绿区内 2 格） | 精准射门；六格门将等概率预判后平均 90% 进球 |
| 其余绿区 | 六格门将等概率预判后平均 65% 进球 |
| 30–90 的绿区外 | 六格门将等概率预判后平均 25% 进球 |
| 91–100 | 偏出：力度过大，球越过球门 |

| 难度 | 绿区宽度（含端点的力度格） | 完整往返周期 | 每次经过深绿线的窗口 |
| --- | --- | --- | --- |
| EASY 简单（默认） | 20，来自原提议 61–80 | 2,880 ms | 80 ms |
| NORMAL 普通 | 11，来自原提议 70–80 | 2,304 ms | 80 ms |
| HARD 困难 | 6，来自原提议 75–80 | 1,984 ms | 80 ms |

原提议区间仍定义宽度，不固定位置。每球绿区完全位于 30–90 内，相邻同宽绿区的起点不同。2 格深绿线在绿区内随机摆放，可以贴任一边缘。命中深绿线就计入完美／精准次数，无论最终进球或被精彩扑出。下表保证门将等概率选六格时，每个玩家目标都得到指定平均值；它们是长期概率，不是每局配额。

| 力度区域 | 门将完全同格 | 同列但上下错层 | 其他列 | 六格平均 |
| --- | ---: | ---: | ---: | ---: |
| 深绿线 | 75% 进球 | 85% 进球 | 95% 进球 | 90% 进球 |
| 其余绿区 | 30% 进球 | 40% 进球 | 80% 进球 | 65% 进球 |
| 绿区外、30–90 | 0% 进球 | 10% 进球 | 35% 进球 | 25% 进球 |

难度只改变可见绿区宽度。力度时序保持普通每格 8 ms、绿区每格 40 ms；更高难度不暗加速度或改变概率。

这是街机规则，不模拟真实足球物理。明确显示六格球门、亮色选中框、绿区、带浅色边线的深绿线及 91–100 红色危险区；游标在蓄力条上下标记，不遮住深绿线。进球时足球飞向已选上／下格，门将按隐藏预判移动；扑救时球停在实际球路的手套接触点。深绿线被扑使用扑救音效和独立结果。动画解释已算出的结果，不通过视觉碰撞反推判定。

难度在 PLAY 前选择，一局内固定。重玩和返回标题保留难度；返回竖屏封面或重启恢复 EASY，静音设置保留范围相同。必须在真机检查细线可读性，以及 80 ms 窗口配合现有 50 ms 界面更新周期的手感；宿主时间计算不代表响应实测。

5. 球和门将动画约 600 ms，随后展示结果与原因 900 ms；超时直接展示结果。每球只记一次。第 1–4 球后回到瞄准，第 5 球后进入总结。
6. 总结显示进球数／5、五次结果、深绿线命中次数，以及再来一局／标题页，不自动重开。

进球、完美、普通绿区进球、绿区扑出、弱射扑出、普通扑出、踢高和超时反馈均已本地化。中英文都采用经过实际 LVGL 布局宽度检查的短文案；简体中文使用仅包含游戏所需字符的思源黑体子集渲染。

底部文案仅在 EASY 或第一球承担教学；NORMAL／HARD 后续每球固定显示一句相邻不重复的鼓励，结果区按判定显示轻松解说。蓄力过程中不换句，也不消耗玩法随机数。完整文案和边界见[动态文案设计](plans/2026-09-16-dynamic-copy-design.zh_CN.md)。

门将六格目标由纯逻辑中的可设种子生成器产生，并在玩家提交目标和力度前锁定。测试注入固定种子／决策，设备集成提供每局种子。未来更高难度不得偷看已提交的玩家选择后暗中修改决定。

### 5.1 独立守门挑战——v1.4

守门挑战沿用射手背后的竖屏视角。AI 射手穿蓝衣，位于前景；玩家控制远端黑衣门将。每次开始时，蓝衣射手用脚部／髋部／身体预备动作真实提示一个已锁定的六格方向：简单显示 900 ms，普通 600 ms，困难 350 ms。提示只显示一次，之后射手恢复准备姿态；不设置假动作，也不在玩家操作后改方向。

玩家循环选择同样六格，第一次按 OK 锁定扑救格并启动时机条，第二次按 OK 扑救。绿区宽度、两格深绿线、0–100 时机路径、五次挑战、4,000 ms 超时及约 600 ms 演出时长与射门挑战一致。结果仅根据预先选定的 AI 方向、玩家扑救格、时机值和预先选定的 0–99 随机值结算一次：

| 时机区域 | 完全同格 | 同列但上下错层 | 不同列 |
| --- | ---: | ---: | ---: |
| 深绿线 | 90% 扑出 | 35% 扑出 | 0% 扑出 |
| 其余绿区 | 65% 扑出 | 20% 扑出 | 0% 扑出 |
| 绿区外、30–90 | 25% 扑出 | 5% 扑出 | 0% 扑出 |

0–29 显示“起跳太早”，91–100 及时机条超时显示“起跳太晚”。同格成功为“稳稳接住”，同列错层成功为“奋力扑出”；不同列为“方向错误”，方向判断到同列但概率判定失败为“判断正确，差一点”。总结按五次中的扑救数计分，“再来一局”保留守门模式。

运行素材包括：射门模式 5 帧红衣射手；守门模式 9 帧蓝衣射手（准备、触球、随摆与六个方向提示）；黑衣门将 7 帧（准备及六格扑救）。它们是存放于 Flash 的真实透明精灵，不是全屏逐帧序列。动画只解释预计算结果，不通过碰撞改变判定。

红／蓝素材画布均为 88 × 88，但准备姿态的实际人物分别为 34 × 65 和 43 × 78 像素（alpha ≥ 128）。因此绘制蓝衣全部动作时统一使用 213/256（83.2%）最近邻缩放，红衣保持原生尺寸。缩放锚点是静止足球的场景坐标 (131,147)，对应精灵局部坐标 (83,52)。这使准备姿态的高度／落地线接近，不改变足球轨迹、时机、方向提示映射或结算。源图片保持不变，缩放画布仍在原 88 × 88 脏区内。

PvP 球衣表示房间玩家身份，不表示本机的控制角色：创建方射门始终红衣，加入方射门始终蓝衣。两台从已同步的比赛身份确定当前射门者球衣，显示相同颜色／动作帧；门将始终使用黑衣素材。抛硬币先后手保持，因此加入方也可能先以蓝衣射门。瞄准、蓄力及锁定等待保留对应准备姿态，不透露方向提示；触球／随摆只在共同动画开始后播放。即使姿态／位置不变，仅换色也会刷新射手区域。单机红／蓝角色映射保持不变。

## 6. 页面与状态流程

```text
开机 → 竖屏封面 → 竖屏菜单（射门／守门／设置／说明）
设置（难度／音效／语言／返回）→ 标题
玩法 → 标题（OK）
射门或守门 → 瞄准 → 蓄力 → 飞行 → 单球结果 → 瞄准（第 1–4 次）
                   └─ 超时 ──→ 单球结果 → 总结（第 5 次）
总结 → 瞄准（同模式再来一局，重置）／标题
任意活动状态 → 退出中 → 封面
```

飞行与超时共用同一套“下一球／总结”分支。重复接收结果不能重复记分。退出时先停止事件生产，再销毁画面。

已实现的 240 × 320 竖屏布局：

| 区域 | 纵向范围 | 内容 |
| --- | --- | --- |
| 顶栏 | y=0–17 | 难度、第 1/5 次、进球数或扑救数、电量 |
| 球场 | y=18–182 | 素材球场、六格目标、红／蓝射手、黑衣门将、独立足球与阴影 |
| 蓄力／结果 | y=205–226 | 192 像素蓄力条、最佳区、游标或结果文案 |
| 底栏 | y=235–319 | 目标／操作文案、互动提示、长按 OK 提示 |

关键文字和控件避开圆角，通常放在 x=16–223 范围内。球场使用已确认体育场中间裁出的原生 240 × 240 素材，活动视口裁切为 y=18–182；三列目标中心保持 x=70／120／170。只有蓝衣射手使用上文有界运行时缩放，其余素材保持原生尺寸。不增加游戏全屏缓冲。固定版本 LVGL 的 RGB565A8 软件变换使用最多四行显示宽度的分条缓冲（240 像素 RGB565 下最多 1,920 字节），不解码整张精灵或画面。现有 LVGL 池和显示缓冲保持不变。

风格：深绿球场、白色门线、明亮足球、原创中性球员像素形象、清晰轮廓。用文字／形状辅助区分区域和结果，不只依赖颜色。蓄力中保留选中目标。用缩放和位移表现纵深，不引入 3D 渲染；避免镜头移动、全屏特效、真实俱乐部品牌和球员肖像。

音频：射门、进球、扑出、偏出短提示，初始每段不超过 300 ms。一个 worker 搭配有界队列，快速转场时丢弃过时音效。声音默认开启，静音只在本次运行中保留；不使用麦克风。

## 7. 开发结构

按用户要求，以 `penalty/` 作为项目策划／设计入口；固件继续沿用当前 ESP-IDF 应用及仓库职责边界：

| 计划模块 | 职责 |
| --- | --- |
| `main/penalty_model.{c,h}` | 纯 C 规则、可复现随机决策、时钟输入、状态转换、每球记录 |
| `main/penalty_ui.{c,h}` | LVGL 对象、布局、反映模型结果的动画 |
| `main/penalty_app.{c,h}` | 输入路由、生命周期、时钟／随机种子适配、音频队列 |
| `tests/test_penalty_model.c` | 规则、时机、状态转换、重复输入及重置的宿主测试 |
| `penalty/assets/`（需要时创建） | 可编辑的美术／音效源素材及授权说明 |

模型不引用 ESP-IDF 或 LVGL 头文件。每局数据包含模式、状态、球次、进球／扑救数、完美次数、玩家／AI 方向、时机值、时间戳、种子和五条尝试记录。每条记录包含方向、时机、对手决策和结果／原因，不含玩家身份或联网数据。

模型由单一执行者修改。按键回调只投递有界事件并返回。LVGL 任务外访问 UI 时持有 `bsp_lvgl_lock()`；音频与语言偏好的 NVS 写入在锁外 worker 中执行。销毁顺序：停止定时器、拒绝旧会话事件、刷新待写入语言、停止并等待 worker 退出，再删除 UI 对象。若 worker 未能停止，保留画面，直到可以安全清理。

`main/main.c` 现为独立游戏入口，开机直达 Penalty。基线演示源文件保留作参考，但不再链接进本游戏。返回封面时停止定时器和服务 worker，重建画面，推进输入代次，再启动服务。已确认封面以 153,600 字节 const RGB565、游戏背景以 115,200 字节 const RGB565 存于 Flash，均不在 RAM 解码整图。仅裁去红衣／门将完全透明的边缘后，游戏素材像素共 404,592 字节；生成的偏移量保留画布锚点，蓝衣画布保留现有缩放取样。源图与转换步骤见[资源说明](../../assets/README.zh_CN.md)。没有增加分区、改引脚或复制 BSP。

固件使用体积优化（`-Os`），因 Penalty 自行设置样式而不包含 LVGL 的默认／简单／单色主题。中文字体保留 4-bpp 字形，使用无损 RLE 解码。保留断言、诊断日志、BLE 安全、恢复、音频及 24 KiB LVGL 池，不以这些能力换取较小镜像。固件／主机门禁和实体验收分别记录。

游戏保持 BSP 的竖屏基线，不再请求四分之一圈旋转。局部缓冲容量保持不变，圆角遮罩继续使用当前 240 × 320 逻辑尺寸，不分配全屏旋转缓冲。停止路径保留幂等竖屏恢复请求作为安全措施。竖屏裁切、六格可读性与操作手感仍需真机验证。

## 8. 存储、异常与性能

- MVP 在 RAM 保存进度、难度和静音设置。退出或断电即丢弃本局，不宣称续玩或成绩已保存。语言是唯一持久保存的游戏设置，从现有 NVS 分区恢复。
- 可选的最佳成绩用带版本号的小型 NVS 记录，在结算时写入。NVS 失败则退化为本次运行成绩，并明确提示未保存。本设计不要求改动分区。
- 飞行／结果阶段忽略无效操作，丢弃旧会话输入。队列溢出不得重复射门或产生任意延后的射门；提交前恢复到瞄准，已提交则完成既定结果。
- 音频初始化失败仍可静音游玩。UI 分配失败时停止已创建资源，显示带长按 OK 重试提示的最小错误页，不保留残缺页面。
- 局部刷新动画目标为 20 FPS，延迟一帧不应改变时间计算；游玩中输入到可见反馈目标不超过 100 ms。两项均需真机测量。
- 游玩中保持 LVGL 对象数量固定，球次之间复用对象；封面只读图片不进入运行堆。新增本地化文案必须同时通过生成字库字符契约和实际 LVGL 宽度检查。真机测试记录最小空闲堆、最大连续空闲块、任务栈余量、显示更新耗时，再据此制定资源预算。

## 10. 首个可玩版本之后再评估的决策

当前 v1.5 实现基线包含“点球决胜、点球练习、守门练习”，以及锁定结果的硬币动画、明确攻守交接、常规提前结束和使用固定内存的不限轮数成对突然死亡；同时保留全程竖屏、按列六格循环、中英文 UI、语言持久保存和仅保存在 RAM 的比分。射门仍使用 90%／65%／25% 标定平均进球率，守门仍使用按难度定时的真实动作提示及同格／同列扑救表。真机仍需验证硬币辨识、交接与提示时机、两位数比分、长按退出、声音同步、堆／栈稳定性和耐久。
