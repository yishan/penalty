# Penalty 混合声音反馈设计

状态：M0–M2 已于 2026-09-16 在本地实现；M3 真机声音验收待完成。本文不宣称已经通过实物听感验证。

## 1. 发现与目标

设备内置扬声器和麦克风，通过 ES8311 codec 接入。当前已确认的应用路径使用 I2S 输出 16 kHz、16-bit、单声道 PCM。Penalty 已初始化 codec、打开 PCM 格式、在独立 worker 中执行阻塞写入，并能生成基础方波音效。

当前游戏没有明确设置输出音量。codec-device 对象以零值初始化，并在打开时重新应用该零音量，足以解释当前静音；Audio demo 会明确设置为 80%，Penalty 则遗漏了这一步。修正该软件缺陷后，仍需通过实机排除第二个板卡或扬声器通路问题。

目标是用简短、容易区分的声音辅助游玩，不形成持续噪声，也不改变既有难度规则。界面操作采用合成的像素电子音；基础输出确认后，触球、扑救和进球采用短 PCM 音效。

## 2. 范围与非目标

本次范围：

- 明确设置输出音量，并让音频链路错误可观察。
- 使用与波形／素材解耦的语义声音事件。
- 短合成界面音与短 PCM 动作／结果音。
- 本次运行内静音、过期事件取消及安全停止 worker。
- 实机校准音量、同步、削波、杂音和耐久。

第一版不做：

- 背景音乐、持续观众环境声、网络音频流、语音控制、录音或持久化音量。
- 每次瞄准移动或每个动画帧都发声。
- 进入绿区或深绿精准线时自动提示。这会实质降低时机挑战的难度，如需加入应另行定义无障碍模式。

## 3. 声音映射

| 事件 | 处理方式 | 优先级 | 播放时机 |
| --- | --- | --- | --- |
| 开始蓄力 | 短促低频合成音 | P0 | 第一次 OK 被接受时 |
| 球鞋接触足球 | 60–100 ms 干脆的 PCM 踢球声 | P0 | 画面触球的 100 ms 节点，而非确认射门瞬间 |
| 普通进球 | 短促双音上扬，可叠加克制的观众 PCM 点缀 | P0 | 足球到达球门时 |
| 深绿线进球 | 独立三音奖励，并沿用踢球／进球声音族 | P0 | 足球到达球门时 |
| 扑救、力量不足、普通绿区或深绿线被扑 | 低沉手套／碰撞 PCM，加短下降尾音 | P0 | 接触门将或停球终点 |
| 踢高或超时 | 较空的下降失败音；超时不播放虚假踢球声 | P0 | 可见偏出时或超时结果时 |
| 菜单确认 | 很短的合成点击音 | P1 | OK 操作被接受时 |
| 切换难度 | 简单／普通／困难使用逐级升高音调 | P1 | 新难度生效后 |
| 声音开／关 | 开启用上扬双音；关闭在静音生效前播放一次下降音 | P1 | 切换时 |
| 五球结束 | 按成绩播放短结束句；5/5 使用独立版本 | P1 | 进入总结页时 |

瞄准移动、自动进入下一球、空闲变暗和封面显示第一版保持安静。

## 4. 播放设计

新增游戏侧语义事件，例如 `PENALTY_SFX_KICK`、`GOAL`、`PERFECT`、`SAVE`、`MISS` 和 `UI_CONFIRM`。规则模型继续与音频解耦，由应用适配层根据已接受的状态迁移生成事件，音频 worker 再把事件映射为音序或 PCM 素材。

`bsp_audio_set_format(16000, 16, 1)` 成功后，明确设置暂定 60% 音量；实机比较 40%、60%、80% 后再确定默认值。音量设置失败必须可观察，界面不能仅因音频格式打开成功就显示 `SOUND`。PCM 写入继续放在按键回调及 LVGL 锁之外。

使用小型有界队列。关键结果音可以替换已经过时的界面点击音；退出、静音和会话切换必须取消队列和当前播放。普通音效原则上不超过 300 ms，五球结束音可放宽至 500 ms；保留起止包络以避免爆音。短素材以 16 kHz、16-bit、单声道 PCM 放在只读 Flash，并按小块送入，不引入运行时解码或整段 RAM 复制。

## 5. 交付顺序

### M0——恢复并诊断输出

设置明确音量，添加仅供开发测试的低／中／高三段音，并分别报告 codec 初始化、格式、音量及首次写入错误。先在实机确认扬声器通路，再扩展声音语言。

### M1——合成反馈

新增语义事件，实现蓄力、触球、进球、深绿奖励、扑救、偏出、菜单确认、难度、静音和五球结束音序；把踢球声对齐到画面触球点。宿主测试覆盖事件映射、优先级、过期声音、静音先后顺序及超时不出脚。

### M2——混合 PCM 素材

将触球、手套扑救及可选的克制进球点缀替换为确认过的 PCM 素材，界面反馈和奖励旋律继续使用合成音。随素材记录来源／许可、格式、时长、字节数、峰值及转换命令。

### M3——实机验收

试听 40%、60%、80%，选择不破音且能够听清的最低档；检查所有结果声音族、静音／恢复、快速退出、立即重进、连续 20 局和 50 次进入／退出。使用慢动作视频确认踢球声开始时间与画面触球相差约 50 ms 以内。确认没有持续堆损失、任务泄漏、看门狗、重启或按键相关杂音。宿主测试和构建通过不能替代该听感验收。

## 6. 验收边界

只有同一份合并固件通过仓库门禁和上述真机清单，才可判定完成。界面显示 `SOUND` 或 PCM 写入返回成功，只能证明软件状态，不能证明实际可听。若设置明确音量后诊断音仍无声，应先检查 ES8311 日志／地址响应、codec 供电、I2S 时钟和数据、扬声器通路及常通外部功放，再调整游戏音效。

## 7. 本地实现记录

- 输出以 16 kHz、16 位单声道打开，并且必须成功设置明确的 60% 音量，界面才会将音频路径显示为可用；格式、音量及 PCM 写入失败分别记录日志。
- `penalty_audio.c` 根据已经接受的模型状态变化生成语义事件。宿主测试覆盖 100 ms 触球边界、超时不起脚、全部结果类型、难度、静音顺序、提示优先级及 5/5 收官。
- 四项有界队列会丢弃过期反馈；动作／结果提示可以替换尚未播放的低优先级界面音。播放仍在 worker 中执行，并在每个 10 ms 分片之间检查停止／静音。
- 原创固定算法 PCM 提供 80 ms 踢球、100 ms 扑救和 110 ms 进球冲击；界面、蓄力、难度、静音、失误、结果旋律及全场结束仍用合成音。
- 完整 ESP-IDF 构建及合并镜像校验通过。这只是软件／构建证据；音量、音色、削波、同步、杂音及耐久仍须按 M3 真机清单验收。
