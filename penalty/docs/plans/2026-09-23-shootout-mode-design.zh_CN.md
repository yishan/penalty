# 点球决胜模式设计

日期：2026-09-23 · 状态：已确认，可进入实现 · 目标版本：v1.5.0

## 目标与范围

新增主玩法“点球决胜”：玩家与 AI 轮流射门和守门，采用五轮点球大战；落后方已不可能追平时提前结束；五轮平分后进入不设轮数上限的成对突然死亡。现有两个独立玩法保留并改名为“点球练习”和“守门练习”，不改变其五球规则。

标题菜单调整为“点球决胜、点球练习、守门练习、设置、说明”。难度、声音和语言继续共用。点球决胜比分仅存在于本局，不持久保存。本版本不包含联网、多人、玩家身份、排行榜、射手假动作或无限长度的完整射门历史。

## 抛硬币与先后手

选择“点球决胜”后进入原创像素硬币页面。按 OK 开始抛掷；模型在动画开始前以相同概率生成并锁定一面：

- 足球：玩家先射门，AI 先守门。
- 手套：AI 先射门，玩家先守门。

硬币使用正面、侧面、背面等固定帧旋转约 1 秒。动画时序、掉帧、重复输入或输入恢复均不能改变已锁定结果。该页 UP／DOWN 无操作；硬币旋转期间忽略短按，长按 OK 仍可安全放弃本局。

落定后页面明确显示玩家先射门或先守门，第二次按 OK 才开始比赛。之后每次切换攻守都采用同一套显式交接：先显示当前比分、轮次和下一角色，再等待 OK。守门回合的射手提示计时只能从这次确认后开始，避免自动切换导致玩家错过方向提示。

## 比赛规则

正式比分只统计进球；玩家和 AI 的扑救数属于附加统计，不能与比分相加。常规阶段双方各最多射 5 球，抛硬币确定的先手在每一轮中保持先罚。

每球完成后分别计算双方常规阶段剩余射门数：

```text
player_remaining = 5 - player_attempts
ai_remaining = 5 - ai_attempts
```

任一方领先数严格大于落后方剩余射门数时，比赛立即结束。领先数等于剩余数时仍可能追平，不能提前结束。该判定在常规阶段每次射门后都执行，因此也能覆盖后罚方已经无需完成最后一球的情况。

双方各完成 5 球仍平分时进入突然死亡。每轮必须按原顺序让双方各射 1 球；双方均完成后，只有一方进、一方未进才结束。本轮第一球不能单独决定胜负。玩法规则不设加赛上限，双方继续成对射门，直到产生胜者。

长按 OK 退出视为放弃本局，不记录胜负。“再来一局”会开始一场新比赛，因此重新进入抛硬币流程。

## 难度与单球行为

整场比赛使用同一个已选择难度，进入突然死亡后也不改变。

- 玩家射门回合沿用当前六格目标循环、技术条、三档绿区宽度、门将预判和已标定进球规则。
- 玩家守门回合沿用当前蓝衣射手真实提示、六格扑救选择、技术条和扑救概率表；简单、普通、困难继续使用 900／600／350 ms 提示时长。
- 难度不会暗中提高 AI 随机结果，也不会允许 AI 在玩家输入后修改已锁定方向。

每球的方向、绿区、深绿线和结果随机值均只生成一次。现有红衣玩家射手、蓝衣 AI 射手、黑衣门将、足球、球场、动画和短音效继续复用。“点球练习”和“守门练习”保持现有独立五球路径，不进入抛硬币、交接、比赛比分、提前结束或突然死亡状态。

## 模型与固定内存架构

将当前含义过载的模式拆成两个概念：

- `session_kind`：点球决胜、点球练习或守门练习。
- `turn_role`：玩家当前射门或守门。

在现有瞄准、技术条、飞行和结果状态外增加等待抛硬币、硬币旋转、先后手结果、回合交接和比赛总结状态。纯 C 模型负责先手、当前角色、常规射门次数、双方进球与扑救、是否进入突然死亡、加赛轮数、当前成对结果及最终比赛结果。

不设加赛上限不能导致无限分配内存。模型只保存累计计数、当前一球、当前加赛对局以及固定长度的最近结果环形缓冲区。所有 LVGL 对象、timer、动画对象和音频 worker 在各球之间复用。射门次数、比分和轮次使用足够宽的计数类型；任何路径都不能继续写入现有仅供五球练习使用的记录数组之外。

每球仍然只结算一次。玩家射门成功时玩家比分加一；射门失败时可按原因增加 AI 扑救统计。玩家守门失败时 AI 比分加一；接住或扑出时玩家扑救数加一。偏出不计门将扑救。模型完成提前结束或成对加赛判断后，才请求显示下一次交接页。

## 界面、美术、音频与文案

标题页使用适配竖屏安全区的五行短菜单。常规阶段顶栏显示阶段、轮次与比分，例如“常规 2/5  你 2:1 AI”。两排各五个紧凑标记显示双方进球／未进。进入突然死亡后，顶栏改为“加赛 N”，结果区只显示当前一对结果，不随轮数无限增长。

硬币是一枚 48–56 像素的原创金色像素纪念币，包含足球面、手套面和清晰的侧面帧。动画只复用一个图片对象，不使用全屏逐帧素材。可选的旋转和落定声音使用短时有界音频事件；音频失败时仍可完整抛掷。

交接页显示比分、常规／加赛轮次、下一角色和“按 OK 开始”。比赛总结显示胜负、最终比分、常规是否提前结束或加赛第几轮决胜、玩家进球数和扑救数，并提供“再来一局／返回标题”。总结页不尝试展示无限长度历史。

所有新增文案均提供中英文版本，加入生成字体子集，并使用真实 LVGL 文字宽度检查。布局验证必须覆盖五行标题菜单、两位数比分、两位数加赛轮数以及圆角安全区。

## 异常与生命周期

- 硬币结果和单球决定只生成一次，延迟帧或输入恢复不能重抽。
- 上一页面的过期按键不能触发抛硬币、确认先后手或开始下一角色。
- 在硬币动画、交接、瞄准、技术条或结果阶段退出时，取消当前比赛，推进输入代次后再重建封面。
- 队列压力下丢弃过期音频和 UI 事件，不能在后续球次重新播放。
- UI 分配或 worker 启动失败时沿用安全降级；音频失败不能阻止游玩。
- 销毁时先停止 timer 和事件生产，拒绝旧会话事件，停止 worker，最后删除 UI 对象。

## 验证与里程碑

### M0——设计

维护本双语设计，并同步主游戏大纲。M0 不修改代码、素材或固件行为。

### M1——纯 C 规则

实现新状态和固定内存比赛数据。宿主测试覆盖两种先手、全部常规攻守顺序、提前结束边界、领先等于剩余数时不结束、五轮平分、完整加赛对局决胜、加赛第一球不决胜、重玩、放弃、重复事件、输入恢复和确定性硬币结果。压力测试至少连续运行 1,000 对平分加赛，不出现内存增长或记录越界；原有练习测试保持通过。

### M2——界面闭环

增加五行标题、抛硬币页面、交接页、比赛顶栏、常规结果双行、加赛当前对局和比赛总结。桌面 LVGL 渲染覆盖中英文、硬币两面、两种先手、常规提前结束、两位数比分和加赛决胜。

### M3——表现

增加可复现的硬币帧和可选有界音效。验证帧边界、正反面辨识、动画与结果一致、字形覆盖、本地化宽度，以及当前内存池内重复进入退出。

### M4——固件与真机验收

运行完整静态、宿主、固件和合并镜像门禁。真机验证硬币两面、实体按键交接、确认后提示可见、提前结束、至少一场加赛、两位数比分、声音同步、长按退出、连续多局、堆稳定、栈余量和耐久。构建成功和桌面渲染不能替代真机验收。
