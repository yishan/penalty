# 点球决胜模式实施计划

> **供 Codex 执行：** 按测试先行方式执行。保留两个练习模式；未经明确授权，不提交、不推送、不刷机、不发布。

**目标：** 交付 Penalty v1.5.0，新增真实规则的点球决胜、锁定结果的抛硬币动画、明确攻守交接、不增长内存的突然死亡，并将原玩法改名为练习模式。

**架构：** 纯 C 模型继续作为规则唯一来源。拆分玩法类型与当前玩家角色，只保存比赛累计、固定五轮标记和定长最近结果；复用现有单球逻辑、LVGL 对象、音频 worker 与生命周期。UI 和音频只表现状态，不参与判定。

## 任务 1：用宿主测试锁定规则

**文件：** `tests/test_penalty_model.c`、`main/penalty_model.h`

1. 定义玩法、角色、硬币、比赛结果、定长历史和比赛计数类型。
2. 先加失败测试，覆盖两种硬币结果、重复输入、固定顺序、提前结束边界、领先等于剩余数时不结束、五轮平局、成对加赛、重玩、放弃和 1,000 对平局加赛。
3. 编译并确认失败原因是功能尚未实现。

## 任务 2：实现纯 C 比赛状态机

**文件：** `main/penalty_model.c`、`main/penalty_model.h`、`tests/test_penalty_model.c`

1. 实现动画前锁定硬币、固定攻守顺序、交接确认、比分、提前结束、成对加赛、定长历史、重玩、放弃和确定性恢复。
2. 保持两个练习玩法各五球，且不进入比赛状态。
3. 运行模型聚焦测试直至通过，再在保持测试通过的前提下整理代码。

## 任务 3：适配场景、互动文案与音效契约

**文件：** `main/penalty_scene.[ch]`、`main/penalty_copy.c`、`main/penalty_audio.[ch]` 及其宿主测试。

1. 先加失败测试，证明当前角色选择正确场景、练习记录互不污染、硬币旋转和落地音效有界。
2. 用明确的玩法／角色辅助函数替换含义过载的模式判断。
3. 运行各聚焦测试直至通过。

## 任务 4：增加双语界面与中文字形

**文件：** `main/penalty_i18n.[ch]`、`main/penalty_ui.c`、本地化／字体测试及生成的中文字体。

1. 先加失败测试，覆盖五行菜单、硬币、交接、常规／加赛顶栏和比赛总结文案。
2. 实现菜单、程序绘制的像素硬币、先后手与交接页、有界比分标记和比赛总结。
3. 运行 `python3 tools/generate-penalty-fonts.py` 重建字体并验证字形与宽度。

## 任务 5：完成生命周期与桌面渲染

**文件：** `main/penalty_app.c`、`tests/penalty_preview/preview.c` 和相关契约测试。

1. 复用现有 screen、timer、事件代次和音频 worker。
2. 确认所有比赛状态都可长按 OK 退出且不记录胜者。
3. 渲染中英文硬币、两种先手、常规、两位数加赛和总结代表画面，检查安全区与对齐。

## 任务 6：对齐版本与文档

**文件：** `penalty/VERSION`、双语 Penalty README 与游戏设计文档。

1. 将版本设为 `1.5.0`。
2. 同步中英文规则、操作、模式名称与验证状态，不修改仓库级变更日志。
3. 运行 `git diff --check` 并检查双语互链。

## 任务 7：完整验证与交付

1. 在 ESP-IDF 5.5.3 环境运行 `./tools/validate.sh --static` 与 `./tools/validate.sh --firmware`。
2. 验证 `build/FoloToy-AI-Passport-Penalty-v1.5.0-full.bin` 及合并镜像检查。
3. 分别报告构建、宿主测试、真机测试与剩余项；刷机前询问；未获要求时不提交或推送。
