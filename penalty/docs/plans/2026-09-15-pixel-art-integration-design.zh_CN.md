# Penalty 像素美术分层与实机接入

## 范围与当前状态

用户已认可接近封面的横屏画风，要求将球场白色色块改为深绿色、说明足球动画方式，并开始拆分素材。这里将白色色块理解为看台下方广告挡板，球门、球网和必要场地线保留白色。整条装饰广告带已统一为深绿色，去除原来的彩色色块和足球图标。

2026-09-15 阶段仅准备美术资源。2026-09-16 用户确认 v0.4 机制后批准接入，本地 v0.5 已使用这些图层。v1.1 确定性样式处理现已将所有当前球场统一为横向草坪明暗条纹、把门将球衣由蓝色改为黑色、在竖屏封面加入固定中文游戏名“点球决胜”，并移除横屏标题页口号。规则与按键映射不变，此前社区提交不变，未刷写设备。生成源图是美术素材，不是运行截图。

v1.1 可先运行 `python3 tools/style-penalty-art.py`，再执行现有封面与游戏素材转换器完整复现。样式脚本从保留的 v1.0 源素材派生当前文件，不重新生成构图，因此既有角色、姿势与版式保持稳定。新版社区封面仅为示意候选图，尚未上传。

## v0.5 已实现的校准与绘制

- `main/penalty_scene.c` 负责可独立宿主测试的表现计算，`main/penalty_ui.c` 负责绘制，玩法模型不变。
- 支撑脚固定在 (120,177)。随摆帧内 (71,52) 的鞋尖接触中心为 (171,147) 的足球近侧边缘。蓄力前至触球时球的位置一致，不靠瞬移衔接；准备／摆腿／随摆沿用已测支撑脚锚点。
- 总表现时长仍为 600 ms：0–49 ms 摆腿，50 ms 起随摆／触球，100 ms 后球开始飞行，600 ms 到达终点。声音仍在提交射门时启动，略早于视觉前摇，听感需实机验收。
- 门将在 56 像素帧中的接触点为左扑 (8,32)、右扑 (49,27)、低位双掌之间 (28,43)。原右扑初步 y=32 落在人物外，已按实际透明度／颜色像素改正。扑出后球停在接触点；进球落在网内，踢高裁剪在顶栏下，超时保持准备姿势，不虚构起脚。
- 活动球场裁剪为 x0–319/y18–182，落点中心 x110/160/210，蓄力条从 y182 开始。足球使用六档预生成尺寸；飞远的球被前景射手正确遮挡。v1.1 竖屏封面保留既有构图并加入固定中文游戏名。
- 转换器生成 264,180 字节四字节对齐的 const 像素：153,600 字节 RGB565 背景及 RGB565A8 角色。不做运行时 PNG 解码、缩放、整屏分配或逐帧新增对象。Alpha 0–1 归零、254–255 归为 255，其余边缘保留。
- 运动时只标记角色、球与阴影的旧／新区块重绘；局部结果逐像素对照整屏重绘，踢高不得覆盖顶栏。宿主测试只在转场时切换方向，与设备一致，不再误将每帧都强制整屏刷新。

使用 `python3 tools/convert-penalty-gameplay.py` 复现资源转换，加 `--check` 可检查一致性（离线需要 Pillow）。实际 LVGL 帧位于 `build/penalty-art-preview/`，确切固件与真机清单见[验证记录](../validation.zh_CN.md)。实机刷新、可读性、声音时机与耐久仍待验收。

## 选定方案

采用静态背景、透明角色动作帧和独立实时足球；界面与反馈由程序绘制。保持画风的同时，落点、力度、门将方向和射门结果仍由游戏实时控制。

考虑过的替代方案：整屏逐帧图片会反复存储背景，结果变化也不灵活；继续用纯几何角色更简单，但达不到已认可的美术效果。因此按本次拆分要求采用分层方式。本次不提交 Git，也不发布到远端。

## 已准备文件

所有文件位于 [gameplay-v2 清单](../../../assets/images/penalty/gameplay-v2/manifest.json)对应目录，清单记录完整提示词、生成方式、切图网格、尺寸及待校准锚点。

| 图层 | 已导出资源 | 运行时用途 |
| --- | --- | --- |
| 背景 | 一张 320 x 240 PNG | 静态球场、深绿挡板、球门、草坪；不含人物、足球、落点框或写死的界面 |
| 射手 | 三张透明 88 x 88 帧 | 准备、摆腿、随摆 |
| 门将 | 四张透明 56 x 56 帧 | 准备、向屏幕左扑、向屏幕右扑、低位接球 |
| 足球 | 18、16、14、12、10、8 像素透明方图 | 独立足球，按距离选择尺寸 |
| 界面／阴影 | 不制作写死图片 | 比分、准确力度区间、落点选择、结果标记、阴影与文字由代码绘制 |

保留原始动作图集及未缩放的单帧；导出只做网格裁切与最近邻缩放，PNG 不包含游戏逻辑。射手支撑脚锚点已按透明度蒙版测量，门将手套位置为初步值，仍需动态校准。接入时检查脚触球：如果现有三帧无法自然接触静止足球，需要补充或修正触球姿势，不能让球突然跳到另一个位置来迁就动作。

## 足球运动与动作顺序

当前 `main/penalty_ui.c` 已有按时间计算的 600 ms 飞行、弧线、足球半径缩小和门将移动。继续使用这种方法，无需生成整屏飞行图。接入新素材时，将相关计算抽出为可独立宿主测试的布局／动画代码。

将飞行时间归一化为限定在 0..1 的 `t`，横坐标从触球点插值到选定落点；纵坐标向结果终点插值，再减去与 `4*t*(1-t)` 成比例的弧线高度。随距离选择更小的足球资源。这是街机表现曲线，不是物理仿真。

| 阶段 | 绘制行为 |
| --- | --- |
| 瞄准／蓄力 | 射手准备、门将待机、球静止，落点与力度实时更新 |
| 起脚 | 短暂摆腿／触球／随摆；仅在校准后的脚触球时刻开始飞行 |
| 飞行 | 按时间更新球的位置与尺寸；门将按已锁定判断移动；阴影可独立绘制 |
| 进球／完美 | 球进入网内；完美射门时门将晚到 |
| 扑出／软弱射门 | 球与手套／低位接球点汇合，随后停住或被遮挡，不能穿过门将继续飞 |
| 踢高 | 球越过横梁，并裁剪在场地区域内，不覆盖界面 |
| 超时 | 不虚构起脚或飞行，直接显示超时反馈 |

不能为了迁就动画修改计球、最佳力度区间或门将已锁定的判断。起脚前摇需要明确分配时间：可以纳入现有飞行动画时长，也可以修改表现时长常量并补测试；不能只在画面上加延迟，导致模型已结算而球还在飞。

新布局初步坐标：球门内部约 x90..230/y44..91，三个落点中心约 x110/160/210，足球起点约 x162/y168，射手支撑脚约 x120/y176。应对照原尺寸背景与触球姿势校准，不能直接套用旧绘制器 x80/160/240 的落点。落点和界面文字用代码绘制，不从 AI 合成稿里截取。

## 原接入清单（第 1–5 步已在本地完成，实机步骤待验收）

1. 将每帧放在明暗背景上检查，必要时清理透明边缘；校准支撑脚、躯干和手套锚点，按原尺寸查看合成后的触球／飞行序列。
2. 增加可复现的资源转换：背景转 const RGB565，角色使用兼容且紧凑的带透明图片资源，足球提前导出多个尺寸。完整 320 x 240 RGB565 背景占 153,600 字节 Flash，不新增整屏 RAM 缓冲；角色格式需同时评估解码、缓存和绘制开销。
3. 接入 `main/penalty_ui.c`，保持玩法规则不变；保留 LVGL 锁、有限对象数量、按键响应、移动前后区域重绘、安全退出和恢复竖屏。静态背景只是内容不变，角色移动后仍需恢复被覆盖的背景区域。
4. 补充独立动画测试和真实 LVGL 截图，覆盖起点／中点／终点、各方向与结果、手套接触、裁剪、五球流程、反复进出；检查实际渲染与资源使用，而不只看美术稿。
5. 运行静态、固件及完整门禁，输出带新版本名的完整 `.bin` 与校验值，保留现有 v0.3 验收／社区文件不变。
6. 按安装说明将新完整固件刷到 `0x0`，不是普通文件拷贝；完整刷写可能重置原设置，请先备份。再实机检查画面、方向键、力度时机、声音、返回封面、刷新和长时间运行。到这一步才需要连接设备。
