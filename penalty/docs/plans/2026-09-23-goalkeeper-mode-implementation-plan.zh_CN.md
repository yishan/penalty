# 守门模式实施计划

> **给 Claude：** 必须按 `superpowers:executing-plans` 逐项执行本计划。

**目标：** 增加独立可选、可复现的五球守门挑战，包含蓝衣射手真实动作提示、玩家六格扑救、时机概率、完整像素动画、中英文界面和已验证固件。

**架构：** 为纯 C Penalty 模型增加角色中立的玩法模式和分模式判定，复用现有六格导航、技术条、事件时间和结果只结算一次机制。渲染继续放在现有 LVGL 场景／界面层，全部新素材以原生尺寸 RGB565A8 常量存放于 Flash。

**技术栈：** C11 宿主模型、ESP-IDF 5.5.3、LVGL 9.5、Pillow 素材转换、原生 RGB565A8 精灵数据、Shell／Python 验证。

---

### 任务 1：记录已确认设计

创建中英文设计与实施计划，并同步游戏策划中的视角、菜单、六格操作、提示时长、扑救概率、素材清单、状态流程和验收边界。执行 `./tools/validate.sh --static`，确保双语配对与链接检查通过。

### 任务 2：以 TDD 增加模式与守门规则

先在 `tests/test_penalty_model.c` 增加四项标题菜单、守门模式进入、对手目标锁定、提示到期、概率表、过早／过晚、扑救计数、重玩和确定性会话测试并观察失败；再最小修改 `main/penalty_model.{c,h}`，直到模型测试通过。

### 任务 3：以 TDD 增加双语文案与字体

先为“射门挑战、守门挑战、扑救数、接住、扑出、失球、扑错方向、判断正确、过早、过晚及守门说明”增加失败测试；再修改 i18n／动态文案，重新生成中文字体，并让文案、i18n 和字体测试全部通过。

### 任务 4：制作并转换动作素材

先让美术契约要求红衣 5 帧、蓝衣 9 帧、门将 7 帧并观察失败；再生成带真实透明通道的源图，导出 88×88 射手和 56×56 门将帧，记录提示词与锚点，更新转换器、清单和 RGB565A8 代码。逐张检查原生尺寸素材，并执行转换器 `--check` 与美术契约。

### 任务 5：以 TDD 渲染两种模式与动作时序

先为红衣五帧、蓝衣六种提示及到期、六个门将终点、守门模式迎面球缩放和目标框增加场景失败测试；再实现分模式场景、菜单和总结布局，运行场景测试及实际 LVGL 预览并检查全部截帧。

### 任务 6：接入生命周期和声音

增加模式安全事件路由、销毁顺序和按键非阻塞契约；复用现有射门、扑出与进球音效，不增加新 worker 或持久化路径。运行 shell 与静态检查直到通过。

### 任务 7：同步权威文档并完成验证

同步 README、策划、多语言、素材和验证文档的中英文版本。依次执行静态门禁、实际 LVGL 预览、固件门禁和完整门禁，验证内容寻址固件归档，并分别报告 Build、Host tests、Device tests 与 Unverified。未经另行授权，不提交、不刷机、不推送、不发布。
